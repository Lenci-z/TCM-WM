# 中西医结合心血管康复方案包与数字化全程管理系统

面向心血管疾病患者的、以 **"中医证型 × 心血管危险分层"双轴模型** 驱动的结构化康复方案与数字化全程管理系统。第一版临床实施以 **冠心病血运重建术后（CAD_PCI）** 人群为切入。

> 需求依据：`任务与设计/中西医结合心血管康复系统设计方案_v0.2.md`（唯一需求来源）
> 技术路线：Python 3.11+ / tkinter / SQLite 本地桌面工具，全中文 UI

---

## 核心特性

### 临床核心（★双轴模型★）

| 特性 | 说明 |
|---|---|
| 双轴处方模型 | 6 证型（气虚血瘀/痰浊闭阻/气阴两虚/心血瘀阻/阳虚水泛/肝阳上亢） × 3 危险分层（低/中/高） → 18 格矩阵（A1–F3） |
| 危险分层判定 | LVEF、血运重建方式、运动试验、METs、心衰症状等阈值规则（高危7/中危4/低危5），满足任一即升级；缺数据保守判高危（医疗安全取向） |
| FITT-VP 全要素处方 | 每格模板含频次/强度（RPE+心率，按分层调 k 系数 0.40–0.70）/时间/类型/总量/进阶 + 八段锦级别 + 中医干预 + 随访间隔 |
| 八段锦分级 | L0 卧位简化3式 ~ L3+ 标准八式+重复，按证型与分层匹配 |
| 安全校验层 | 配伍禁忌（十八反十九畏）+ 妊娠禁忌 + 病种特异禁忌（穿刺点/DAPT），处方生成时硬校验 |
| 三级预警 | 红（24h处置）/黄（72h）/蓝（仅患者端）共 16 条预警规则，处置闭环留痕 |
| 医师审核签发 | 处方必经医师审核签名，不可跳过（临床决策支持工具定位） |
| 处方 PDF 导出 | reportlab 导出中文处方单（五大处方整合样式） |

### 工程能力

| 特性 | 说明 |
|---|---|
| 规则全配置化 | 分层阈值/证型特征/处方模板/八段锦/预警/禁忌全部存表，GUI 可视化可调，零硬编码 |
| 多病种架构 | 全表含 `disease_category` 字段 + `disease_config` 参数集表；当前仅启用 CAD_PCI，其余 6 病种预留 |
| 引擎纯逻辑化 | 引擎层不碰数据库：接收 dict、返回 dict，可脱离 DB 单测（Repository 层统一数据访问） |
| 数据安全 | AES-256-CBC 加密患者隐私字段 + bcrypt 密码哈希（正式版可对接医院加密方案） |
| 认证与权限 | 登录 + 失败锁定（5次/15分钟）+ RBAC 权限矩阵（医生/护士/管理员）+ 审计日志 |
| 数据看板 | 依从性打卡 + 康复指标统计看板 + CSV 导出 |
| 数据健壮性 | DB 健康检查 + SQLite 锁重试 + 一键备份恢复（SQLite backup API） |
| 配置化启动 | config.ini 统一配置（DB 路径/密钥/医院名/字体/日志），启动系统.bat 一键部署 |

## 技术栈

- **Python 3.11+** + **tkinter**（GUI，标准库）+ **SQLite**（存储，标准库）
- reportlab ≥ 4.0（处方单 PDF 导出，中文字体 msyh/simhei）
- cryptography ≥ 42.0（AES-256-CBC 加密）、bcrypt ≥ 4.0（密码哈希）
- 无 Web 框架，纯本地桌面工具

## 快速开始

### Windows 一键启动

双击 `启动系统.bat`：自动探测可用 Python（避开 Microsoft Store 别名陷阱）→ 缺依赖自动安装 → 启动系统。

### 手动启动

```bash
# 1. 安装依赖（Python 3.11+）
pip install -r requirements.txt

# 2. 启动（首次自动建库 + 导入种子数据）
python app/ui/main.py
```

首次启动会进入登录页，按提示**初始化管理员账号**。主窗口 7 Tab：患者管理 / 评估录入 / 处方管理 / 随访管理 / 数据看板 / 依从性打卡 / 规则库维护（仅管理员可见）。

## 架构设计

分阶段演进后的目标架构（P2 解耦后）：

```
┌─────────────────────────────────────────────┐
│  UI 层（tkinter：登录 + 7 Tab，全中文）        │
│  薄层编排：取数 → 调引擎 → 存结果              │
└────────────────────┬────────────────────────┘
                     ▼
┌─────────────────────────────────────────────┐
│  Repository 层（app/repo.py）                 │
│  集中全部 SQL 访问；加密/解密透明处理           │
└────────────────────┬────────────────────────┘
                     ▼
┌─────────────────────────────────────────────┐
│  规则引擎（纯逻辑，不碰 conn）                 │
│  分层判定 → 证型判定 → 矩阵编码 → 处方生成     │
│  → 安全校验 → 预警引擎 → PDF 导出             │
└────────────────────┬────────────────────────┘
                     ▼
┌─────────────────────────────────────────────┐
│  数据层：17 表 + 病种参数集 + schema 迁移      │
│  （全表含 disease_category，多病种扩展）       │
└─────────────────────────────────────────────┘
```

- **引擎纯逻辑化**：引擎函数接收参数集 dict、返回 dict，不依赖数据库连接——可脱离 DB 做纯逻辑单元测试，为技术栈迁移留余地。
- **规则外置**：分层阈值、证型特征、处方模板、八段锦分级、预警、禁忌全部配置化存表，GUI 可视化调整，不藏在代码里。
- **多病种设计**：`disease_config` 已建 7 个病种条目，第一版仅启用 `CAD_PCI`，后续病种启用无需改表结构。
- **安全分层**：AES-256 加密患者隐私字段、bcrypt 密码哈希、登录失败锁定、RBAC 权限矩阵、操作审计日志。
