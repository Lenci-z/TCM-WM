### 4.2 P1 问题（需修复）

#### P1-1：`patient_view.py` 第177行 — `_load_form` 对 Entry 调用 `.set()` 会崩溃

**文件**：`app/ui/patient_view.py` 第177-178行

**问题**：
```python
for key, var in self.pvars.items():
    var.set("")  # ← Entry 没有 .set() 方法，Combobox 才有
```
`self.pvars` 中混合了 Entry（proc_date, stent_count, lesion_vessel_count）和 Combobox（proc_type, incision_type, anticoagulation）。`tkinter.Entry` 没有 `.set()` 方法，执行到 Entry 时会抛 `AttributeError`。

**对比**：同文件 `_new` 方法（第194-203行）正确区分了类型：
```python
for var in self.pvars.values():
    if isinstance(var, ttk.Combobox):
        var.set("")
    else:
        var.delete(0, "end")
```

**影响**：GUI中点击"载入选中"患者时崩溃，无法编辑已有患者信息。

**修复**：将177-178行改为与 `_new` 方法相同的 isinstance 分支逻辑。

---

#### P1-2：`prescription_view.py` 第320行 — `tk.simpledialog` 未导入

**文件**：`app/ui/prescription_view.py`

**问题**：第9行导入为 `from tkinter import ttk, messagebox, filedialog`，缺少 `simpledialog`。但第320行调用了 `tk.simpledialog.askstring("医师签发", ...)`。

`import tkinter as tk` 不会自动加载 `tkinter.simpledialog` 子模块。

**影响**：GUI中点击"签发处方"时崩溃，无法完成签发操作。

**修复**：第9行改为 `from tkinter import ttk, messagebox, filedialog, simpledialog`，或第320行改为 `simpledialog.askstring(...)`。

> 注：同目录 `followup_view.py` 第11行已正确导入 `simpledialog`，可参照。

---

#### P1-3：`prescription_view.py` 第298-300行 — 保存处方时只更新5个字段，医师调整的其他字段丢失

**文件**：`app/ui/prescription_view.py` 第296-300行

**问题**：
```python
if rx.get("rx_id"):
    update_row(self.conn, "prescription", {k: rx[k] for k in
             ("baduanjin_level", "aerobic_duration", "aerobic_freq", "rpe_min", "rpe_max")},
             "rx_id=?", (rx["rx_id"],))
```
更新已有处方时只写入了5个字段，但 `_apply_adjust` 可能还修改了 `hr_min`/`hr_max` 等。这些调整不会被持久化。

**影响**：医师调整心率区间后保存，重新载入发现调整丢失。

**修复**：将更新字段扩展为完整的可编辑字段集，或改用全字段更新。

---

#### P1-4：`alerts.py` — `ALERT-B-001` 蓝色预警条件 `consecutive_met` 未实现

**文件**：`app/engine/alerts.py` `_eval_condition` 方法 + `data/seed/rule_alert.json` 第185行

**问题**：种子数据中 `ALERT-B-001`（连续达标激励）的条件为 `{"op": "consecutive_met", "count": 1}`，但 `_eval_condition` 方法未实现 `"consecutive_met"` 操作符，直接返回 `False`。

**影响**：蓝色激励预警永远不会触发。不影响安全性，但功能缺失。

**修复**：在 `_eval_condition` 中添加 `consecutive_met` 分支，或在种子数据中标注为待实现。
